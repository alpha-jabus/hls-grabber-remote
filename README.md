# HLS Grabber 2.2 — Firefox + сервер предпросмотра HLS

После явного включения перехвата для вкладки сканирует HTTP(S)-запросы `.m3u8` в этой вкладке Firefox и запоминает заголовки запроса в памяти браузера. Может работать в двух режимах:

- **Удалённый сервер:** делает кадры JPEG / короткий GIF, получает длительность и разрешение через `ffprobe`, скачивает видео с помощью `ffmpeg` **на сервер, сразу шифруя AES-256-GCM**.
- **Локальный режим:** скачивает видео **на ПК** через исходный Linux Native Messaging помощник. Без установленного сервера предпросмотры недоступны.

Автоматическая загрузка кадров выполняется **только после открытия popup и только если удалённый режим включён**; до шести найденных потоков за открытие, последовательно. GIF формируется по кнопке. Можно скопировать команды `ffplay` и `ffmpeg` для запуска на ПК. Это позволяет отличать основной ролик от рекламного, но не гарантирует распознавание встроенной рекламы.

## Версия 2.2: очередь, отдельная вкладка, шифрование

- Вместо ошибки при занятых слотах загрузки попадают в **FIFO-очередь**; `HLS_MAX_JOBS=2` теперь означает число одновременно выполняемых задач. Очередь живёт в памяти, а её метаданные записываются на диск. После перезапуска задания из очереди помечаются ошибкой — ссылки и cookies не записываются на диск ради возможности возобновления.
- По кнопке **«↓ Загрузки»** открывается отдельная вкладка Firefox со статусами, очередью и размерами. Списка задач в маленьком popup больше нет.
- Для каждого HLS URL показаны состояния «В очереди», «Скачивается», «Уже скачано». Повторная команда скачивания того же *точного URL* возвращает уже существующую задачу без дубля; после неудачи можно повторить. **При обновлении подписанной ссылки с другим токеном** программа может считать её новым URL.
- Загрузки **всегда шифруются AES-256-GCM на сервере в процессе скачивания**: `ffmpeg` пишет в pipe, Python шифрует поток сразу в `*.mp4.hlsaes` / `*.mkv.hlsaes`. Чистый MP4/MKV не появляется на диске сервера, включая временные `.part`. Формат потоковой записи отличается от обычного MP4: MP4 внутри шифротекста фрагментированный, но воспроизводится после расшифровки.
- **Ключ шифрования** (base64, 32 байта) создаётся один раз в `~/.config/hls-grabber-server/encryption.key` с правами `600` и **не совпадает с API-токеном**. Никогда не выкладывай его в GitHub, не отправляй в чат, храни резервную копию в безопасном месте. **При потере ключа файлы восстановить нельзя.**
- Для расшифровки скопируй *.hlsaes и `server/hlscrypto.py` **на свой ПК**, безопасно перенеси туда ключ и выполни:

```bash
python3 -m pip install cryptography  # при необходимости; или sudo apt install python3-cryptography
python3 hlscrypto.py --key-file /private/encryption.key "video.mp4.hlsaes" "video.mp4"
```

  Скрипт проверяет аутентификационный GCM-тег до публикации выходного файла. При ошибке он удаляет незавершённый `.part`, и готовый MP4 не появляется. **Не храни копию ключа рядом с файлами на незащищённом общем диске.**

**Обновление сервера c 2.1:** скопируй обновлённую папку `server/` на хост, установи `sudo apt install ffmpeg python3 python3-cryptography`, затем от имени обычного пользователя повторно запусти `bash server/install-server.sh`. Установщик сохранит существующий API-токен, создаст AES-ключ, если его ещё нет, и перезапустит пользовательский systemd-сервис. Старые нешифрованные файлы автоматически не изменяются, прежняя история задач сохраняется.

**Установка обновлённого расширения:** v2.2.0 в архиве *не подписана* Mozilla. Для постоянного обычного Firefox нужно отправить этот XPI на подпись в AMO как новую версию и установить подписанный XPI. Не пытайся ставить неподписанный XPI поверх подписанного в release Firefox.

## Быстрее всего: сервер по SSH-туннелю (без домена)

**На Linux-сервере** скопируй папку `server/`, затем:

```bash
sudo apt install ffmpeg python3 python3-cryptography  # Debian/Ubuntu
cd server
./install-server.sh
```

Установщик генерирует случайный 256-битный токен и записывает его в `~/.config/hls-grabber-server/server.env` (права `600`). Сервис слушает **только `127.0.0.1:8765`**. Скачанные **зашифрованные** файлы находятся в `~/hls-grabber-data/downloads/`, задания — в `~/hls-grabber-data/jobs/`. Проверить:

```bash
systemctl --user status hls-grabber-server
# Не пересылай вывод следующей команды — он содержит секрет:
grep '^HLS_API_TOKEN=' ~/.config/hls-grabber-server/server.env
```

На **своём ПК** сделай SSH-туннель (держи терминал открытым):

```bash
ssh -N -L 8765:127.0.0.1:8765 user@server.example.com
```

В настройках расширения включи «Использовать удалённый сервер», заполни:

- Адрес API: `http://127.0.0.1:8765`
- API-токен: значение `HLS_API_TOKEN` из файла на сервере (только само значение, без `HLS_API_TOKEN=`)

Нажми **Сохранить → Проверить**. Трафик до удалённого сервера идёт внутри защищённого SSH-туннеля; локальный HTTP используется только между браузером и `127.0.0.1`.

Если система не поддерживает user-service при выходе из SSH, включи linger (`sudo loginctl enable-linger ИМЯ_ПОЛЬЗОВАТЕЛЯ`) или используй системный сервис под отдельным пользователем.

## Подключение напрямую по HTTPS

Если есть домен, настрой reverse proxy с сертификатом TLS, например Caddy (`server/Caddyfile.example`). Backend по умолчанию всё равно слушает только loopback; proxy подключается к нему локально. В расширении укажи `https://video-api.example.com`.

**Не** открывай порт `8765` для внешнего мира через `HLS_BIND=0.0.0.0` без дополнительной защиты. **Не** подключайся к публичному серверу через обычный HTTP: расширение отклоняет HTTP, кроме localhost/127.0.0.1/::1.

Для доступа через VPN/overlay-сети можно использовать SSH-туннель к VPN-адресу либо HTTPS reverse proxy.

## Установка Firefox-расширения

1. Firefox 140+ → `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение».
2. Выбери `extension/manifest.json` (или XPI из архива).
3. Открой иконку расширения, нажми **Включить перехват на вкладке**, разреши Firefox доступ к сайтам (запросы HLS часто идут с других CDN), затем запусти видео или обнови страницу.
4. **⚙ Сервер** → адрес + токен → **Сохранить** → подтверди передачу данных в запросе Firefox → **Проверить**.
5. В списке появятся миниатюры, длительность, качество и статус загрузки; подробная очередь доступна по кнопке «↓ Загрузки». Кнопка **▶ GIF 3 с** формирует анимированный предпросмотр. **↓ На сервер** сохраняет видео на сервер; файлы не передаются обратно на ПК.

Для локальной загрузки вместо этого выключи удалённый режим и установи на ПК помощник: из корня проекта `./install.sh`. Требуется `ffmpeg` в Linux. Кнопка станет **↓ На ПК**. Firefox Flatpak/Snap может потребовать отдельной настройки Native Messaging.

**Временные дополнения** пропадают после перезапуска Firefox. Для обычной постоянной установки Firefox требуется XPI с подписью Mozilla; `hls-grabber-unsigned.xpi` в архиве не подписан.

## Безопасность и границы защиты

- В удалённом режиме расширение отправляет URL подписанного потока и HTTP-заголовки **только на явно указанный сервер**. Это могут быть **Cookie**, `Authorization`, `Authorizations` и другие чувствительные значения сайта. Серверу нужно доверять.
- Отдельный, случайный **API-токен сервера** отправляется в `Authorization: Bearer ...` только к серверу. Проверка сервером делается через сравнение с защитой от тайминговых атак. На неуспешную авторизацию отвечает `401`.
- Настройки (включая API-токен) хранятся в локальном профиле Firefox (`storage.local`), **не в зашифрованном хранилище**. Используй защищённый профиль ОС и не синхронизируй вручную эти настройки.
- Сервер не ведёт журнал тел запросов или URL и не хранит cookies/токены сайта в файлах заданий. Сервер сохраняет только метаданные задач и видео. Однако аргументы команд `ffmpeg`/`ffprobe` могут быть видны в списке процессов серверному пользователю и администраторам (`ps`, `/proc`). Запускай сервис от **отдельного Linux-пользователя без лишних прав**.
- Применяются ограничения тела HTTP-запроса, объёма ответов, времени на `ffprobe`/`ffmpeg`, максимума одновременных превью (2) и загрузок (2), предельного размера файла (по умолчанию 8 GiB). Лог ошибок ffmpeg не сохраняется.
- URL верхнего уровня должен быть HTTP(S) и при начальной проверке разрешаться **только в публичные IP** (loopback/private/link-local/metadata адреса отклоняются); допускаются исходные порты 80/443. `ffmpeg` получает ограничение протоколов, чтобы не загружать HLS-сегменты через `file:` и другие схемы.
- **Важно: проверка верхнего URL НЕ обеспечивает полной SSRF-защиты!** Внутри HLS бывают редиректы, альтернативные плейлисты, сегменты, новые DNS-ответы. Для публично доступного сервера обязательно ограничь **исходящий сетевой доступ процесса** к внутренним сетям / metadata endpoint на уровне firewall или изолированного контейнера. Не запускай бэкенд на машине с привилегированным доступом к внутренним службам. Используй сервер с минимальным доступом и отдельным непривилегированным пользователем.
- Для HTTPS проверка TLS осуществляется системными библиотеками/FFmpeg. Принудительный TLS для remote настроен в расширении; `redirect: error` исключает пересылку тела API-запросов на другой URL.
- Отсутствует поддержка DRM. Сохранение контента возможно, только если позволяет источник и права на него. Истекающие авторизационные данные нужно обновлять повторным воспроизведением видео.
- Очередь не сохраняет URL и заголовки: после рестарта ожидавшие или выполнявшиеся задачи отмечаются `failed`; возобновление не реализовано. Зашифрованные неполные `.part` удаляются при штатном обнаружении ошибки.

## Требования и API

- Backend: Linux / Python 3.9+ / `ffmpeg`, `ffprobe` и Python-пакет `cryptography` (Ubuntu: `python3-cryptography`).
- Firefox WebExtension: Manifest V2 (`webRequest.onSendHeaders`, `storage.local`, `nativeMessaging`).
- `GET /api/v1/health`, `GET /api/v1/jobs`, `POST /api/v1/preview` и `POST /api/v1/download` принимают `Authorization: Bearer <HLS_API_TOKEN>`.
- Preview JSON: `{ "url":"https://.../master.m3u8", "headers":[{"name":"Referer","value":"https://..."}], "mode":"image" }`, где `mode` может быть `image` либо `gif`.
- Download JSON: `{ "url":"https://.../master.m3u8", "headers":[], "name":"video", "format":"mp4" }`.
- Ответ preview — JSON с `image` (base64 JPEG/GIF), `mime` и `info` (`duration`, `width`, `height`). Это позволяет показывать предпросмотр без отдельных секретных URL к файлам.
